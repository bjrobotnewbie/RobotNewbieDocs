# AWML (Autoware Machine Learning)

## 概述

本文档为 **AWML (Autoware Machine Learning)** 技术介绍文档，涵盖项目定位、架构、功能模块、技术栈、部署流程、应用场景、优势及迭代规划，旨在帮助开发者、算法工程师及自动驾驶研发人员快速理解AWML的设计理念、技术能力与落地价值。AWML是面向Autoware自动驾驶生态的开源机器人MLOps框架，专为自动驾驶感知、预测、规划等机器学习任务打造，打通自动驾驶模型从数据治理、模型训练、迭代优化到工程部署的全流程链路，是Autoware从传统规则驱动架构向**AI数据驱动架构**升级的基础设施。

## 项目简介与定位

### 2.1 项目定义

AWML 是由 Tier IV 主导开源、适配 ROS/ROS2 生态的自动驾驶专用机器学习与MLOps框架，全称 Autoware Machine Learning。框架聚焦自动驾驶场景下的AI模型工程化落地，解决传统自动驾驶机器学习开发中**数据零散、训练碎片化、部署适配难、迭代效率低**的行业痛点，为Autoware全系版本提供标准化、生产级的AI模型开发与运维能力。

区别于通用MLOps框架，AWML深度耦合自动驾驶业务特性，适配车载多传感器（相机、激光雷达、毫米波雷达）数据格式，支持2D/3D感知、车道分割、场景理解、交通灯识别、轨迹预测等自动驾驶任务，是目前Autoware官方唯一配套的机器学习工程化基础设施。

### 2.2 定位

- **生态适配层**：无缝对接Autoware Universe/Core全系架构、ROS2标准接口，实现AI模型与自动驾驶规则模块的高效协同，支撑“AI主驾+规则副驾”的主流自动驾驶技术范式。
- **自动驾驶MLOps全链路平台**：覆盖数据采集、智能标注、模型训练、验证评估、优化量化、车载部署、迭代更新的完整闭环。
- **量产落地工具链**：面向车载嵌入式、边缘计算设备优化，提供模型轻量化、推理加速、精度校验能力，满足自动驾驶量产安全性与实时性要求。

## 整体架构设计

AWML采用**分层模块化架构**，低耦合、高可扩展，各层级独立可替换，同时保障全流程链路贯通，整体分为五大层级，适配自动驾驶AI开发全生命周期。

### 3.1 数据治理层（Data Layer）

作为框架底层基础，聚焦自动驾驶车载数据的标准化治理，解决实车数据冗余、标注成本高、有效样本稀缺问题。能力包括车载日志数据批量采集、脏数据清洗、关键场景数据挖掘、自动标注、半自动辅助标注、伪标签生成，同时支持多传感器数据对齐与格式标准化，为模型训练提供高质量数据集。

### 3.2 模型开发层（Model Layer）

提供统一的模型开发基座，内置标准化模型接口与开发规范。框架定义通用 `BaseModel` 基类，统一封装训练、验证、测试、优化器配置、指标统计、推理输出转换等通用逻辑。开发者仅需聚焦网络结构与业务逻辑开发，即可快速接入自定义模型，大幅降低模型适配成本。同时内置Autoware量产常用预训练模型库，覆盖感知、分割、预测等场景。

### 3.3 训练调度层（Training Layer）

基于配置化驱动的训练引擎，支持单机与分布式训练，集成自动化超参调优、训练过程监控、模型版本管理、指标日志回溯能力。兼容OpenMMLab系列工具库，Autoware内置的CenterPoint 3D检测、车道分割等模型均基于该层级完成标准化训练与迭代。

### 3.4 部署优化层（Deployment Layer）

面向车载实时推理的优化模块，实现训练模型到量产可用模型的格式转换与性能优化。提供标准化模型转换流水线，支持PyTorch权重文件一键转换为ONNX通用格式，再编译为TensorRT高性能推理引擎，大幅提升车载设备推理速度、降低算力占用。

### 3.5 生态对接层（Eco Layer）

无缝对接ROS2消息机制、Autoware业务模块（感知、规划、控制、定位），支持模型推理结果与自动驾驶业务链路的无缝流转，同时适配Autoware模型资产管理体系，实现预训练模型的自动下载、校验、版本管理。

## 功能模块

### 4.1 智能数据闭环模块

区别于通用AI框架，AWML主打**自动驾驶主动学习闭环**，是其差异化能力。框架可自动筛选实车行驶中的难样本、边缘场景数据，通过自动标注与伪标签技术生成标注数据，经人工审核后迭代训练新模型，实现“实车采集-数据筛选-智能标注-模型迭代-上车部署”的持续优化闭环，完美适配自动驾驶场景长尾问题优化需求。

### 4.2 标准化模型库

内置18+量产级预训练模型包，覆盖四大业务领域，全部适配Autoware车载场景并完成精度与速度优化：

- **感知任务**：2D/3D目标检测、交通灯识别、障碍物分类（集成CenterPoint 3D检测模型）；
- **场景分割**：车道分割（EgoLanes）、全局场景分割（SceneSeg）、可行驶区域分割；
- **预测任务**：车辆、行人、非机动车轨迹预测；
- **辅助定位**：视觉匹配、场景特征提取辅助定位模型。

### 4.3 一键式模型部署工具链

提供命令行轻量化部署工具，封装完整模型优化与部署流程，无需复杂手动配置。标准化部署流水线：`PyTorch checkpoint\(\.ckpt\) → ONNX → TensorRT\(\.engine\)`，支持自定义配置文件快速切换任务与模型，适配不同车载硬件平台，保障推理实时性满足自动驾驶量产要求。

### 4.4 模型资产管理系统

通过Ansible自动化工具实现模型包的批量下载、完整性校验、版本管理与本地目录规整，统一管理分布式存储中的预训练模型资源，解决多设备、多版本开发场景下模型混乱、版本不兼容、资源冗余问题，适配团队协同开发与量产交付流程。

### 4.5 可扩展自定义开发能力

提供标准化的模型新增、模块扩展规范，开发者可基于 `BaseModel` 基类快速自定义新模型，通过DataModule适配自定义数据集，依托配置化系统快速接入训练、评估、部署全流程，无需改造框架底层，具备极强的业务扩展性。

## 技术栈

AWML采用主流稳定的开源技术组合，兼顾研发效率与量产稳定性，技术栈如下：

- **基础框架**：PyTorch（模型训练）、OpenMMLab（视觉算法支撑）；
- **部署加速**：ONNX、TensorRT（车载推理优化）；
- **机器人生态**：ROS2、Autoware Universe/Core；
- **工程工具**：Ansible（模型资产管理）、CLI命令行工具（一键部署）；
- **MLOps能力**：主动学习、自动标注、版本管理、训练监控、指标评估。

## 标准部署与训练流程

AWML固化自动驾驶AI模型标准化研发流程，全流程自动化、可追溯、可复用，具体步骤如下：

1. **数据采集与预处理**：采集车载多传感器日志数据，完成数据清洗、场景筛选、传感器对齐；
2. **智能标注**：通过框架自动标注、伪标签生成海量基础标注，人工复核修正，构建高质量数据集；
3. **模型训练与调优**：基于内置模型或自定义模型，通过配置文件启动训练，自动完成超参优化、指标评估、模型筛选；
4. **模型格式转换与优化**：将训练完成的ckpt权重文件转为ONNX通用格式，再编译为TensorRT高速推理引擎；
5. **车载部署验证**：适配ROS2与Autoware业务链路，实车测试推理精度、实时性，完成场景适配校验；
6. **迭代更新**：收集实车运行难样本，进入下一轮数据迭代闭环，持续提升模型泛化能力。

部署命令示例：

```Plain
autoware-ml deploy \
    --config-name <task>/<model>/<config> \
    +checkpoint=mlruns/<task>/<model>/<config>/<run_id>/artifacts/checkpoints
```

## 应用场景

### 7.1 自动驾驶算法研发

支撑Autoware全栈AI算法迭代，替代传统手工建模方式，高效完成目标检测、车道识别、轨迹预测等感知与预测任务开发，适配L2及以上高阶辅助驾驶、自动驾驶场景。

### 7.2 车载AI模型量产落地

通过模型量化、推理加速、硬件适配优化，将训练模型转化为车规级可用的推理模型，满足车载边缘设备低算力、高实时性、高稳定性的量产要求，适配车企、Tier1量产交付流程。

### 7.3 机器人智能感知开发

依托ROS2通用生态，可拓展应用于服务机器人、巡检机器人、无人车等智能设备的视觉感知、场景理解任务，为各类机器人提供轻量化MLOps解决方案。

### 7.4 高校与企业科研教学

开源免费、架构清晰、文档完善，可用于自动驾驶机器学习、机器人MLOps方向的科研实验、项目教学与算法创新验证。

## 优势

- **场景深度适配**：专为自动驾驶多传感器场景设计，区别于通用MLOps框架，原生适配车载数据与业务逻辑，无需二次大幅改造。
- **全链路闭环能力**：独家集成自动驾驶主动学习闭环，解决行业长尾场景优化难题，实现模型持续迭代升级。
- **Autoware原生兼容**：官方配套框架，完美适配Autoware全系架构，实现AI模块与规则模块高效协同，兼容性、稳定性远超第三方框架。
- **轻量化量产友好**：极简部署流程、硬件适配性强，模型优化方案成熟，兼顾推理精度与速度，满足量产落地标准。
- **高可扩展性**：模块化分层设计，标准化接口，支持自定义模型、自定义数据集快速接入，适配多样化研发需求。
- **开源生态完善**：持续迭代更新，配套完整文档、模型库、工具链，社区活跃，适配国内外自动驾驶开源生态。
