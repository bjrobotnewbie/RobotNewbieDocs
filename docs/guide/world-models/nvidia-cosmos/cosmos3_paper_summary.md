# 论文总结：Cosmos3全模态世界模型

## 一、绪论部分

论文围绕NVIDIA发布的Cosmos3模型展开，该模型面向物理人工智能（Physical AI）领域打造统一全模态大模型，核心定位是把过去拆分的多类AI模型整合进一套网络架构。在物理AI落地场景中，机器人、自动驾驶、智能基建等智能体需要完成环境感知、逻辑推理、动作决策、未来环境仿真四项工作，传统技术方案会采用多套独立模型分工实现：视觉语言模型负责看图问答理解场景、视频生成模型做画面仿真、世界动力学模型推演环境变化、视觉动作模型输出控制指令。以家用收拾餐桌机器人举例，传统方案需要VLM识别餐具、VLA模型规划抓取动作、动力学模型模拟桌面环境变化，多模型串联部署带来算力冗余、多模型对齐难、部署链路冗长等问题，Cosmos3的设计思路就是消除这种模块化割裂，单模型同时实现理解与生成两大核心能力，输入输出自由组合文本、图像、视频、音频、动作五类模态数据。

从能力落地来看，Cosmos3划分Super、Nano、Edge三个尺寸版本，其中Super（64B参数）、Nano（16B参数）开源权重对外开放，Edge（4B参数）后续更新发布；评测数据显示，经过后训练微调的专用版本在图文、图生视频开源榜单登顶，面向机器人策略的Nano-Policy-DROID在RoboArena机器人基准取得最优成绩。同时项目开源配套五大类合成数据集、Cosmos-HUE人工评测基准与全套工程代码，方便学术界与产业开展物理AI相关实验，本讲后续从模型架构、数据设计、训练流程、实验效果四个模块逐层拆解原理。

## 二、模型架构原理

Cosmos3依托\*\*混合Transformer（MoT，Mixture-of-Transformers）\*\*作为主干网络，整体架构由多模态编码器、Token排布规则、双支路MoT主干、多模态位置编码、多模型尺寸分支五部分构成，整套架构区分自回归推理支路（Reasoner）与扩散生成支路（Generator），一套主干拆分两套参数通路是全模态统一实现的核心设计。

### 2.1 多模态专属编码器

模型对文本、图像/视频、音频、动作四类数据分别设计独立编码器，所有模态编码完成后映射至同一个隐特征空间，不同模态额外增加可学习模态嵌入向量，用来帮助Transformer区分数据类型。

1. **图像&视频编码器**：采用双编码分支设计，一条面向理解任务使用ViT编码器，Patch尺寸$16\times16$，经过两层MLP聚合特征，搭配DeepStack特征聚合算法、帧时间戳嵌入方案，用于Reasoner支路的图像特征提取；另一条面向生成任务复用Wan2.2配套VAE编码器，VAE在空间上压缩$32\times32$、时间维度压缩4倍，训练阶段VAE权重冻结，仅用线性层把VAE输出映射到模型隐藏维度。两种编码结果分别送入自回归序列与扩散序列，实现同一套网络兼顾图像理解和图像生成。
2. **音频编码器**：使用专用音频VAE，原始音频采样率48kHz，单段处理步长1920采样点，折算每秒生成25个音频Token，音频VAE同样冻结权重，仅通过单层线性映射对齐模型特征维度，所有音频数据最终转化为序列嵌入参与扩散生成流程。
3. **动作编码器是本模型差异化设计重点**：动作指代机器人、自动驾驶车辆、人肢体运动等所有环境状态切换的驱动变量，不同设备原生控制参数格式差异极大，机械臂关节坐标、车辆转向角、人手关键点属于完全异构数据，Cosmos3先做统一动作表征，把所有动作拆分为本体位姿、执行器位姿、抓取状态三类子特征：本体/执行器位姿采用6D旋转+3D平移的9维表征，抓取区分开合1维参数或多手指关键点高维参数；自动驾驶仅保留本体位姿，人形/机械手数据完整包含三类特征。
   在Token化阶段，针对不同设备设置独立输入输出投影层：某类设备原始动作向量$\boldsymbol{x}$经过专属权重$W\_{in}^{(k)}$、偏置$b\_{in}^{(k)}$映射为模型通用隐Token，解码时再通过对应$W\_{out}^{(k)}$还原原始动作数值。不同设备共用MoT主干权重，仅首尾映射层参数独立，既实现跨设备动作知识共享，又保留各类硬件的动作特征差异性。

### 2.2 Token排布与生成模式

所有输入数据编码后拆分为两大连续序列：**自回归AR子序列**在前、**扩散DM子序列**在后，是整套模型实现多任务复用的排布准则。

1. AR子序列：存放文本Token、ViT编码后的图像/视频Token，使用因果自注意力，仅能依据前文预测下文，对应VLM类理解任务，完成问答、场景推理、细节定位；
2. DM子序列：存放VAE压缩的图像/视频、音频、动作Token，采用全向双向注意力，依靠AR的上下文做条件约束，通过去噪迭代生成新内容，对应图像、视频、音频、动作生成类任务。
   在DM序列内部，遵循“干净条件Token在前、带噪声目标Token在后”规则，同时固定排布优先级：视觉→音频→动作，依靠这套统一排布，仅改变输入输出Token组合就能切换任务，下面逐个说明常用生成模式：

- 文生图：AR段仅放提示词文本，DM段存放带噪图像隐Token；
- 文生视频+音频：AR为文本，DM是带噪视频+后置带噪音频Token；
- 图生视频：AR存放提示词，DM前置干净原图VAE特征、后置带噪后续帧；
- 控制图转视频：前置边缘/深度等干净控制帧，后置待生成RGB噪声帧；
- 动作三类任务：前向动力学（给动作生成后续画面）、逆向动力学（由画面反推动作）、策略生成（同时输出动作+未来画面），仅修改DM内动作、视频的干净/噪声排布即可。

### 2.3 MoT双支路混合Transformer结构

每层Transformer拆分成Reasoner、Generator两个独立塔状通路，两套通路拥有各自LN归一化、注意力映射、FFN全连接参数，初始化权重源自预训练Qwen3-VL模型，继承成熟图文理解能力，两条通路仅在跨模态联合注意力处做特征交互。

1. Reasoner支路：查询$Q\_{AR}$、键值$K\_{AR}/V\_{AR}$仅在AR序列内部做因果注意力，和DM数据互不修改自身特征，保证文本、图像理解能力不会被生成任务破坏；
2. Generator支路：查询$Q\_{DM}$ 需要拼接 $\left\[K\_{AR};K\_{DM}\right]$、$\left\[V\_{AR};V\_{DM}\right]$做全局全注意力，也就是生成过程全程可以读取前面所有文本、参考图上下文，实现提示词精准约束生成结果；
   简单概括：理解部分只看自己历史序列，生成部分能回看全部前文信息，参数分开训练、信息跨支路互通。

### 2.4 改进型3D MRoPE多模态位置编码

常规RoPE只适配文本一维位置，原版3D MRoPE能拆分空间高、宽、时序三维坐标，但无法统一音频、动作、视频不同采样帧率的时间尺度，Cosmos3新增**绝对时序调制**优化：

1. 坐标分配规则：文本Token的高宽时序三数值完全相等，退化为一维RoPE；图像/视频占用独立高、宽、时序坐标；音频、动作仅使用时序坐标，高宽固定为0；AR与DM序列之间强制预留固定15000时序间隔，消除文本和首帧位置过近带来的画面畸变问题；
2. FPS时序缩放：设定基准时序速率$\text{TPS}_{base}=6$（对应24FPS视频经过4倍VAE压缩），任意模态实际时序步长$\delta t=\frac{\text{TPS}_{base}}{\text{TPS}\_{now}}$，比如60FPS视频单帧对应的时序跨度更小，在位置编码上拉开不同帧率素材的时间间隔，实现24/30/60FPS视频、48kHz音频、不同采样频率动作共用一套时序坐标系，从编码层面保证音画同步、动作和画面时序匹配。

### 2.5 模型尺寸划分

三个版本基于不同基座大模型初始化：

- Edge：2B稠密Transformer，28层，隐藏维度2048，自研基座权重，面向端侧嵌入式部署；
- Nano：基于Qwen3-VL 8B初始化，36层、隐藏维度4096；
- Super：基于Qwen3-VL 32B初始化，64层、隐藏维度512；
  三个版本主干都是MoT双支路架构，仅参数量和超参区分，方便研究者按需选用算力匹配的模型。

## 三、数据集构建方案

数据整体拆分为Reasoner推理数据集、Generator生成数据集两大体系，两套数据训练目标不同：推理数据侧重图文/视频标注、问答类监督样本；生成数据侧重海量无标注音视频+结构化动作素材，并且引入自研五大物理仿真合成数据集补齐现实稀缺场景。

### 3.1 Reasoner推理数据集

总样本2420万，分为预训练2200万、微调220万：预训练以海量图文对、纯文本为主，扩充OCR、目标检测、通用视觉问答数据；微调大幅提升视频数据占比，聚焦自动驾驶、机器人、智能基建三大物理AI细分领域，新增空间定位、物理常识判断、任务规划类标注数据。
数据清洗采用双阶段流水线：先基于Qwen3-VL-Embedding做嵌入聚类去重，余弦相似度高于0.95的重复样本剔除；再使用Gemma-4作为AI裁判，从可信度、完整性、正确性三项1\~5分打分，预训练保留≥2分样本，微调严苛筛选≥5分高质量样本，规避错误标注导致模型物理常识崩坏。细分方向上补充手术机器人视觉、仓储空间、交通异常、多模态驾驶决策等小众场景标注，补齐通用数据集缺少的物理交互内容。

### 3.2 Generator生成数据集

遵循渐进式训练逻辑：预训练（海量图文音）→中训练（新增动作、控制类素材）→专项后训练（细分图生图/图生视频/机器人专用小数据集）。

1. 图像视频预训练：原始素材78亿图片、30亿视频，经过黑边裁剪、场景切分、嵌入聚类去重、画质打分过滤，最终保留7.67亿图片、3.48亿视频，分辨率覆盖256/480/720P，画面比例囊括16:9、1:1等主流规格；
2. 中训练核心补充自研SD系列五大合成数据集：SD-PhyxSim刚体/流体物理仿真素材、SD-RobotSim多机型机器人操作数据、SD-DriveSim全场景自动驾驶片段、SD-SynHuman人体交互视频、SD-Warehouse仓储人机协同画面，弥补现实中物理碰撞、精密机械手操作等稀缺画面；同时新增深度/边缘/分割图+原图配对的控制生成素材，支撑视频迁移任务；
3. 音频数据：从原视频剥离音轨，用声源分离模型拆分人声、环境音，过滤无配乐人声画面、无效旁白素材，只保留画面动作对应的原生音效，保证生成时声音和可视事件匹配；
4. 动作数据集：合计61.3万小时素材，四大板块：人本位自摄手部动作（67.4%）、自动驾驶路采（16.3%）、多机型机器人开源数据集（8.7%）、相机运动推算素材（7.5%），所有动作统一归一化至$\[-1,1]$区间后编码入模型。
   **标注关键优化**：放弃自由文本caption，全部采用结构化JSON标注，把画面物体、光影、镜头、时序动作、音效拆分为固定字段，训练时模型学习结构化描述，推理时借助Reasoner把用户短句扩充为完整JSON提示词，大幅提升生成精准度。

## 四、全流程训练方案

整体训练分两大阶段：先单独训练Reasoner推理分支，训练完成后用Reasoner权重初始化Generator生成分支，生成支路再经过预训练→中训练→专项后训练三步微调。

### 4.1 Reasoner训练

1. 预训练：优化目标是自回归交叉熵，AdamW优化器，大模型学习率$5\times10^{-5}$、ViT编码器$5\times10^{-6}$，学习率先线性升温再余弦衰减，序列上限16k Token，采用平方根归一化损失平衡长短样本权重；
2. 监督微调：混合少量预训练数据（1:4配比）防止通用能力退化，针对性加权采样机器人、自动驾驶小众数据集，迭代8200步，调低学习率做精细化适配，落地各类物理领域问答能力。

### 4.2 Generator训练

生成模型全部基于\*\*整流流匹配（Rectified Flow Matching）\*\*损失优化：给原图隐变量$x\_0$插值加噪声$x\_\sigma=\sigma\epsilon+(1-\sigma)x\_0$，模型预测噪声与原图的位移速度，通过MSE损失收敛，图像/视频/音频/动作使用独立噪声采样方案。

1. 预训练：多分辨率并行训练（256/480/720P），不同分辨率设置不同噪声偏移系数，训练时混合文生图、文生视频、图生视频、续帧四类任务，采用Token打包策略，固定单批次总Token上限74000，填充零冗余提升GPU利用率，此阶段Reasoner参数全程冻结，只更新Generator权重；
2. 中训练：在原有图像视频音频数据基础上，新增动作、控制帧数据，训练配比固定：图像10%、常规视频40%、音视频8%、动作25%、通用控制视频20%、驾驶专用控制5%，动作损失权重放大10倍加快收敛，模型在此阶段学会动作→画面、画面→动作双向映射关系；
3. 专项后训练：从中训练通用权重微调专用模型：
   - 文生图Super：两轮微调，先用千万级混合图数据通用优化，再用47万超高精度图集精调；
   - 图生视频Super：混合原图数据+2万合成视频，锁定480P、8秒（189帧）规格优化；
   - Nano-Policy-DROID：基于DROID机械手数据集微调，新增专用动作解码层，推理仅4步扩散采样，降低机器人部署时延，实现实体机械臂闭环操控。

## 五、工程落地基础设施

整套训练推理底座分为数据SILA平台、训练框架、推理部署、评测平台四块：

1. SILA数据架构：采用Lance列式存储替代传统数据库，统一存储原始数据、嵌入、标注、特征，分布式Ray流水线完成数据清洗、嵌入、筛选，支持断点续算、闲置算力复用，十亿级素材去重效率提升10倍；
2. 训练基建：混合分片数据并行HSD+上下文并行Ulysses，自定义双通路可变长注意力内核，针对GB200硬件优化FlashAttention/NATTEN算子，搭配选择性激活重计算、TorchCompile编译VAE，异步断点存储避免保存权重占用训练耗时；
3. 推理部署：Reasoner依托TensorRT-LLM/vLLM加速，Generator基于vLLM-Omni部署，支持CFG并行、上下文拆分、模型CPU卸载等加速手段，单卡/多卡灵活切换；
4. 评测系统：自动化指标+人工Cosmos-HUE评测双路线，自动化用VLM打分，人工把视频拆成原子化是非问题，从物理规则、几何、画面保真、语义四项打分，规避自动化指标对物理错误的漏判。

## 六、实验结果分析

### 6.1 Reasoner评测

通用多模态基准上Super版得分73.7，接近闭源Gemini3.1Pro；**机器人、自动驾驶、智能基建三大垂类全面优于Qwen、Gemma系列开源模型**，在空间定位、物理因果、驾驶碰撞判断、仓储场景问答等专项基准领跑，验证统一架构对物理类理解任务的优势。

### 6.2 Generator生成评测

1. 图文：Cosmos3-Super-Text2Image在UniGenBench总分91.36，开源榜单第一，英文/中文字符渲染能力优于主流开源图生模型；
2. 视频：PAIBench、Physics-IQ物理仿真基准优于Wan、Veo等开源/闭源竞品，HWB人体动作评测Super71.9分，大幅领先同类生成模型，物理合理性突出；
3. 音视频：音频和画面事件同步精度顶尖，碰撞、机械音可以精准对齐画面接触时刻；
4. 控制迁移：边缘、深度、地图驱动生成任务超越老版Cosmos-Transfer专用ControlNet架构；
5. 动作&机器人：前向/逆向动力学指标优于DepthAnything、各类世界模型，Nano-Policy-DROID登顶RoboLab、RoboArena真实机器人榜单，落地实机抓取测试。

## 七、总结与行业价值

Cosmos3核心创新是依靠MoT双支路架构实现理解、生成一体化全模态建模，打破过往多模型割裂的行业痛点，一套权重可按需切换图文、音视频、机器人、自动驾驶数十类任务。开源全量权重、合成数据集后，一方面可以用模型生成海量物理仿真数据，降低真实场景采集成本；另一方面作为基座快速微调各类机器人、自动驾驶专用小模型，加速物理AI从仿真落地真实设备，后续迭代方向聚焦更长时序环境生成、端侧轻量化Edge模型落地。当前文件内容过长，豆包只阅读了前 64%。
